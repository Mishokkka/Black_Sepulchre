# Salvage и события D66

После каждого нетерминального боя обе стороны делают Salvage D6: **1 = 0; 2 = 10; 3 = 15; 4 = 20; 5 = 25 Supply; 6 = 20 Supply или 1 Intel.** За 1 Intel один собственный reroll, новый обязателен. Затем один глобальный D66 (две независимые D6, десятки и единицы). В D два результата, в D3 три; победитель выбирает один, при ничьей Defender.

После выбора provisional события одно окно платного reroll: первым проигравший, при Draw Defender; при отказе второй игрок. 2 Intel, один новый обязательный D66, максимум один платный reroll на всех. 64 без legal сектора требует технического перевыбора события из остальных 35 без новой платы; это не дополнительный управляемый reroll. Случайные кампанийные результаты и решения сохраняются, повторный запрос не бросает заново.

**Lesser Territory:** меньше контролируемых секторов, затем меньше non-Home, затем меньше Supply до наград этого aftermath, затем случайный roll-off. «Следующий бой» у глобального события - следующий реальный бой кампании; личные эффекты следуют своему явно названному владельцу/Force. Неиспользованный эффект этого боя истекает. Повтор одного token не создаёт копию. Награды на отсутствующих eligible ID пропадают, если замена не названа.

# Optional STF и памятка боя

Включается только по общему решению после восьми боёв. Создание в Home за 250 Supply, пустой отдельный roster: cap 75% AL по RC, deployment 50% AL Effective. В начале своей Activation выбрать одну Force для 2 Actions/2 MP; другая не действует. Supply, Intel, Package и Window общие. Покупки в выбранную Force при её окончании в своём Supplied секторе. Transfer между Force только при совместном присутствии и Reorganise. Main Force по-прежнему нужна для Armoury/Doctrine и Home assault; STF не осаждает Home и не заменяет Main Force в обязательном кризисе.

Две Field Forces не складываются в одном бою: Defender выбирает одну, вторая не участвует и при потере сектора отступает вместе с первой. STF имеет обычные Rest/Participation/Distinguished относительно собственных relevant боёв, не дополнительный доход. Находящиеся с Main Force local garrisons по-прежнему отдельный Pool. Пустой STF не продаётся обратно. Этот модуль добавляет стратегические решения, но не вторую Activation.

## Переходы

**Strategic -> Declaration -> Mission -> Muster -> Reveal -> Battle -> Result pending -> Aftermath choices -> Logistics -> next Activation.** Финал переводит Aftermath в Terminal. Occupation/Unmanned используют собственный короткий переход без Battle и не запускают его награды. Forced Encounter проходит обычный реальный Battle. Поздний переход на правила при battle_count ≥17 сразу планирует финал после разрешённой переходной Logistics.

**Секретность:** один игрок не получает через API закрытый commitment, выбор PACT/WAR или ещё не раскрытую случайную цель. Проверку и сохранение состава выполняет сервер, не только UI. После принятия обоих раскрывает обе версии атомарно. Recon Lock меняет этот порядок явно. Текущая стадия приложения блокирует запоздалые покупки и смену loadout.

**Одновременность:** каждое действие несёт request ID и ожидаемую версию состояния. Один серверный переход проверяет turn/phase, ресурсы, route, наличие unit/slot и меняет их вместе. Повтор того же запроса возвращает прежний результат; конфликт версии просит обновить состояние. Двойное нажатие, reconnect, второй браузер и повтор webhook не дают второй награды или нового броска. Скрытые выборы не попадают в общедоступный журнал до reveal.

**Случайность:** сервер сохраняет результат до ответа клиенту; reroll - отдельное разрешённое событие со стоимостью и ссылкой на заменяемый roll. Все награды имеют ключ battle + side + source + target + ordinal. Только явно повторяемые источники получают следующий ordinal. Фактические боевые dice можно бросать на столе; их кампанийные последствия фиксируются по подтверждённым фактам.

**Исправления:** сначала оба подтверждают Result, затем preview Casualty/Salvage/D66 и оставшиеся выборы. Intel/Supply на reroll и платные event choices берутся из уже доступного кошелька, не из ещё не применённых наград. Выборы резервируют расход в preview. Итог Aftermath применяется одной транзакцией. Исправленный Result создаёт новую ревизию и переигрывает расчёт из того же исходного snapshot с теми же сохранёнными dice, не второй income. Если уже начат следующий ход, зависимые ходы блокируются до согласованного отката. Не удалять окончательно ID, пока расчёт не подтверждён.

# Пакет боя, переход и проверка

## Что видит игрок

Перед боем: карточка миссии и схема, поле, зоны, роли, составы после reveal, активные Honours/Scars/Assets, расписание Pool, один overlay кризиса. Приложение скрывает неотносящиеся правила. В раунде: доступные Actions, одноразовые uses, scoring и hazards именно этой фазы; правила Warhammer выполняются за столом.

После боя подтвердить: победитель/VP и обязательный gate; какие ID реально вошли и какие уничтожены; Deeds и Distinguished; выполненные миссионные Actions/доставки/особые natural rolls; relevant причинные теги потерь (например, Toxic/взрыв); Withdrawal и итоговое положение. Если данные уже отмечались по ходу партии, итоговая форма подставляет их. Не требовать повторного ввода того же факта.

Автоматически: цены, допустимость, снабжение, таймеры, rewards, casualty dice, Scar выбор из legal строк, ранги, Stage, crisis thresholds, начисления и списания. Решения о покупке, retreat destination, риске лечения, Honour, ending и PACT/WAR остаются игрокам. Приложение не «угадывает» эти предпочтения по вероятности победы.

## Переход с 2.1/2.2

Только между боями до объявления hostile target; обе стороны одновременно. Сохранить ID, XP, Damage, предметы, Supply, ownership и mission history; пересчитать карту/CR/Supplied. Не выдавать стартовую армию, деньги или Stage Grants повторно. При переходе с 2.1 один раз выдать по 25 Local Supply в два своих Supplied non-Home сектора; с 2.2 местные суммы уже существуют и не удваиваются. Увеличение cap не пополняет сам запас.

Использованные Window flags, paid steps и ранги сохраняются. Неприменимые улучшения -> pending. Armoury не возвращает разницу цены. Старые одноразовые эффекты получают явный scope/expiry без продления; неоднозначный выбор показывается обоим до миграции. Choir поднять до порога уже открытого Reveal. Фазу кризиса вычислить по реальному battle_count; при ≥17 следующий бой финальный. Emergency debt изначально 0, пока не применён Emergency Muster.

## Что проверено и что проверять в партиях

Аналитические проверки сопровождают исходник: симметрия карты и финальных координат; доступность Local cap для стартовых защитников; монотонность Casualty; равномерное раскрытие F2; достижимый график шести ключей и двух Primes; исчерпание Window без боя; покрытие 33 миссий и 36 D66. Проверка геометрии не является измерением winrate.

После каждых четырёх боёв приложение сравнивает тип боя, AL, фракцию, первого игрока, начальные/прибывшие Effective points, победителя, VP/gate, расходы лечения и экономику. Для осад отдельно Initial/Pool и раунд прибытия; для кризиса ключи/Instability/Override. Не менять несколько параметров по одной партии. Утверждённые tier и War of Attrition сохранены; новая боевая модель кооперативного кризиса требует натурного playtest.
