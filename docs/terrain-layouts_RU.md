# Поле боя: анализ и генерация для The Black Sepulchre

## От чего отталкиваемся

- В [Event Companion 11-й редакции](https://www.warhammer-community.com/en-gb/articles/lszdpzmc/new40k-download-the-new-event-companions-today/) у каждого сочетания турнирных миссий предусмотрены три варианта поля; у вариантов меняется расположение террейна и учитываются задачи сторон. Это полезный ориентир по разнообразию, но турнирные карты рассчитаны на другие миссии и стандартное поле 60×44″.
- В основных правилах 11-й редакции различаются *terrain area* (её граница) и размещённые в ней *terrain features*, которые могут быть плотными или лёгкими. Для укрытий, видимости и движения важны конкретные элементы. Основные правила и актуальные материалы доступны на [странице загрузок Warhammer Community](https://www.warhammer-community.com/en-gb/downloads/warhammer-40000/).
- У Black Sepulchre версии 2.2.1 собственная геометрия и требования: поля 44×30″, 44×44″ и 60×44″, координаты объектов, сопоставимые укрытия, доступ на уровне земли в 3″ к каждому объекту и проходы для имеющихся баз. Она имеет приоритет для этой кампании. Результат генератора — авторский вариант поля кампании, а не официальная карта GW.

## Особые случаи миссий

| Случай | Что показывает схема |
| --- | --- |
| THREE, FOUR, FIVE, SIX, CROSS, TRIANGLE, FINAL | Начальные позиции и типы объектов по правилам кампании. Совпадающие объекты имеют одну позицию и отдельные строки в таблице. |
| C3 | Короткие стороны как зоны расстановки и центральная полоса шириной 8″. |
| D3 | Три полосы шириной 4″ в ничейной зоне. |
| I2 | Три дорожки и objective в центре каждой дорожки: x = L/6, L/2, 5L/6. Это исправляет ранее применявшийся шаблон THREE. |
| B3 и E1 | Старт и путь процессии/поезда; сам объект движется по правилам миссии и не считается террейном. |
| C2 | Начальная позиция платформы и линия её движения. |
| H3 | Начальная безопасная зона радиусом 18″, которая уменьшается по правилам миссии. |
| PACT | Симметричный террейн и свободные прямые линии к каждому Seal с обеих сторон. Реальная видимость зависит от расставленных физических моделей террейна. |

Координаты платформы, реликвий, других переносимых или движущихся объектов на схеме — только начальные; дальнейшее перемещение происходит за столом.

## Как строится вариант

Генератор v1 получает публичный идентификатор боя, миссию, размер поля и начальные позиции её объектов. Он воспроизводимо выбирает разные области террейна; оба игрока видят одинаковую схему. Данные армий и скрытый Signal F2 не используются. При перебросе миссии создаётся другая схема. При обычном обновлении страницы схема восстанавливается из данных боя; отдельной записи в базу она не требует.

Области ставятся парами с поворотной симметрией, чтобы дать сторонам сопоставимое количество плотного и лёгкого террейна. Минимум одна пара плотных элементов размещается в зонах, следующие элементы предпочитают ничейную территорию. Для небольших полей используются меньшие площади. Алгоритм оставляет не менее 2″ между площадями, свободную область радиусом 3″ вокруг точек и проверяет на сетке подход пехоты к каждой точке с обеих сторон. Для PACT области дополнительно не пересекают прямые линии к Seals. Отдельные правила осады могут намеренно делать расположение самих объектов несимметричным.

На схеме прямоугольники — площади, линии внутри — примеры физических стен или препятствий. Таблица даёт размеры и координаты верхнего левого угла каждой площади; координаты объектов считаются по центру. Категории Dense/Light согласуются игроками до партии. Области не обязаны быть сплошными непреодолимыми препятствиями; проверка подхода консервативно считает их таковыми.

Генератор не знает геометрию конкретных миниатюр и реальной постройки, не рассчитывает все линии видимости и не гарантирует турнирный баланс. Перед игрой проверьте проход для самых крупных баз, высоту и размещение элементов и видимость в PACT; при необходимости по взаимному согласию подвиньте элемент. Особые Assets расставляются отдельно в положенный им момент.

## Сопровождение

Миссии используют существующий `createTable`. Для существующих боёв схема вычисляется в браузере; она не хранится отдельно в Supabase. Поэтому правила и порядок вычисления версии 1 нельзя менять для уже начатых боёв: новый алгоритм должен иметь отдельную сохранённую версию схемы или сохранять сами координаты. Исправление координат I2 находится в общем движке и должно быть развёрнуто вместе с клиентом и серверной функцией; ранее сохранённые состояния автоматически не переписываются.
